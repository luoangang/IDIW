# DeepSeek 情报周报

## 使用方式

1. 在服务器的 `.env` 中设置 `DEEPSEEK_API_KEY`，不要提交密钥到仓库。运行 `python platform_main.py init-db` 创建 `weekly_reports` 表和任务开关字段；现有采集记录不受影响。
2. 启动或重启 API 与调度器。在管理平台的“情报周报”页，针对需要的监控任务勾选“每周自动生成”。默认关闭，避免为无关任务产生模型费用。
3. 系统从北京时间周一 10:00 起生成**上一完整自然周**（周一 00:00 至下周一 00:00，结束时刻不包含）的周报。服务器中途停机时，恢复后会补排该周；同一任务同一周只保留一份记录。页面也可手动排入上周报告或查看失败原因。

周报读取 `monitor_resource_matches.first_matched_at` 落在该周的**新增匹配**，按监控任务隔离，不直接扫所有来源表。每份报告最多取最新 200 条，将标题、来源、摘要前 400 字和发布日期发送给 DeepSeek；原始数据与证据链接保存在本地，全文不会上传。报告展示总匹配数和实际纳入模型输入的条数，超过 200 时属于抽样摘要，不应视为覆盖全部文章。无新增记录时生成空周报告，不调用模型。

模型必须返回结构化概览、要点和后续观察；每个要点都要引用本次输入中存在的证据编号。平台校验这些编号，拒绝截断响应和未知引用，并在页面提供原文链接。模型可能仍误判相关性或误读摘要，周报是辅助研判，不替代人工核对原文。来源内容可能包含恶意指令，提示词要求忽略，页面也只按纯文本展示。

失败自动间隔 10 分钟重试，最多 3 次；失败后可在页面再次生成上周报告。API：`GET /api/v1/weekly-reports`、`GET /api/v1/weekly-reports/{id}`、`POST /api/v1/monitors/{id}/weekly-reports` 和 `PATCH /api/v1/monitors/{id}/weekly-report-settings`。配置了 `PLATFORM_TOKEN` 时沿用平台的 Bearer 鉴权。
