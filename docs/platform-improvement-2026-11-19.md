## 关键设计说明

### 助手范围校验

`journal_scope` 仅属于助手草案，支持 `selected` 与 `all_chinese`。确认创建时仍向现有监控表写入实际 `journal_keys`，没有新增数据库表或列。

- 当前明确的“所有/全部中文期刊”请求由平台保留范围约束，后续修改时间不能被模型静默降为默认选刊。
- 全部范围要求覆盖所有已登记、可用的中文期刊包目录；缺少包、目录读不到、实际选刊不足均不能生成创建凭据。
- 大型目录未全部放进模型上下文；模型能看到目录数量，平台负责校验标识，模型编造的期刊标识不能确认。
- 确认签名绑定实际期刊目录，目录变化需重新检查。
- **尚未实现自动分批覆盖全部期刊。** 当前超出单包上限会明确阻止，需要缩小范围或分别建立任务，不能说已采集全目录。
- 834 为目录条目数，不是今天逐刊可用率或去重后的独立期刊数量。

### UI 与交互

保留原生 HTML/JavaScript，不引入 SPA 框架、前端构建服务或 CDN。Lucide 1.8.0 仅复制所需图标及创建函数，ISC 许可位于 `crawler_platform/vendor/lucide/LICENSE`。

别名按回车提交，按规范化文本去重；修改草案会清除旧确认凭据。模型请求失败保留当前输入、对话和草案。前端请求有 75 秒上限，创建请求超时时提示先检查任务列表，不自动重试写入。

参数侧栏保留原有 Schema 控件和期刊标签选择器。尚未实现跨刷新保存助手会话或草案；刷新仍会清空当前会话。

### 插件升级保护

导入前检查候选参数能否容纳当前默认配置及各任务覆盖参数。不兼容或有活动执行时，在修改包状态前拒绝升级。升级准备时保存旧元数据；依赖安装等准备阶段失败则恢复旧名称、清单、默认配置及 `ready` 状态，不将原可用包整体停用。

这不是 MySQL DDL 的事务回滚承诺：已经执行的兼容性加列可能保留，旧运行文件、旧环境和已采集数据不会删除。安装进程突然被强制终止后的 `installing` 恢复仍待专门处理；不要盲目删除修复锁或并行导入。

安装期间禁止修改默认配置，避免候选安装失败恢复时覆盖用户刚保存的设置。入队时使用 `LOCK IN SHARE MODE` 与升级注册锁协调；本机 MySQL 为 5.7.44，不支持 `FOR SHARE`，该兼容性问题已在恢复调度时发现并修复，错误事务已回滚。

### RSS 匹配

`keyword_policy=union` 保留旧行为：主词、别名、额外词、关键词组之间为 OR。

`keyword_policy=groups_only` 只按 `keyword_groups` 匹配：组内 AND、组间 OR。普通词不能绕过组条件。空组和空词直接报配置错误；`match_mode=all` 明确不做主题匹配。

它只是 RSS 本地文本过滤，不等于统一检索 AST、源站原生布尔检索或语义相关性保证。本轮没有自动收窄具身智能、军事智能体两个现有任务的词表。

## 运维入口

- 新增 `PLATFORM_TRUSTED_HOSTS` 和 `PLATFORM_PUBLIC_ORIGIN`：默认仅本机，跨源网页不能执行管理写操作；命令行沿用 Token 鉴权。反向代理部署必须明确域名与公开源，详见 README 的服务器访问保护。这不是新增用户系统，也不代替公网鉴权。

- 页面：`/system`，API：`GET /api/v1/system/status`，沿用既有 API 鉴权。
- 状态页读取本机 CLI 服务锁、数据库队列及最近五条失败/部分完成记录。不扫描文章结果表。
- OS 锁在进程退出或崩溃时释放，残留的文件本身不代表服务还活着。锁保存在运行目录 `locks/`。
- CLI API、Scheduler、默认 Worker 各自只允许一个同名实例；需要多个 Worker 可用 `platform_main.py worker --instance second`，不同名称独立加锁。
- 这是单机进程存在性检查，不是分布式监控，也不证明循环无卡死、外网正常或文章完整。WSGI/容器/其他主机进程可能不在本机 CLI 锁中，需结合部署管理器检查。
- 平台服务日志：运行目录 `logs/serve.log`、`logs/scheduler.log`、`logs/worker-default.log`。时间带 `+08:00`；每文件约 5 MB，保留四个备份，每角色总量约 25 MB。
- 单次插件日志：运行目录 `runs/<execution_id>/process.log`。网页运行详情提供相对位置；不通过网页任意读取服务器文件。
- 新失败运行的 warnings 写入已有 `package_runs.result_json`；旧失败记录未自动回填。页面最多展示前 100 项 warnings，标明总数。

## 复验方法

```powershell
.\.venv\Scripts\python.exe -m pytest tests_platform -q -p no:cacheprovider
.\crawler_platform_runtime\environments\rss_multi_feed\1.1.0\Scripts\python.exe -m unittest discover -s crawler_packages/news/rss_multi_feed/tests -v
.\.venv\Scripts\python.exe -X utf8 scripts/verify_live_platform.py
```

`scripts/verify_assistant_ui.mjs` 使用 Playwright 和模拟 API，检查 1280、1440、1920 桌面宽度、标签/来源/参数操作、二次确认、异常恢复、系统状态和 warnings 转义。设置 `PLAYWRIGHT_MODULE` 为已安装 Playwright 的包路径，或在可解析的 Node 环境中安装 Playwright；本机验收使用 Edge 无头模式。截图放 `.test_tmp/assistant-ui/`，不提交运行缓存。

`scripts/upgrade_rss_package.py` **会真正导入 RSS 包**，不是只读检查；必须先确认空闲。它核对默认配置、任务来源设置、结果表和环境，报告不包含订阅地址、密码或密钥。

`scripts/verify_live_browser.mjs` 在真实本机服务上读取助手、系统状态、任务和来源页面，检查无脚本错误或桌面横向溢出，同源无效草案进入参数校验；不调用模型、不创建任务。截图保存在 `.test_tmp/live-ui/`。

可选真实数据库回归：设置 `$env:PLATFORM_TEST_MYSQL='1'` 后运行 `python -m pytest tests_platform/test_mysql_integration.py -q`。需要建库/删库权限，只创建随机 `crawler_it_<32位十六进制>` 临时库并在结束时删除，数据库名称不接受外部输入，不使用业务库。不要在无测试授权或严格限制资源的生产数据库上启用；普通回归默认跳过。

## 后续优先级

1. 助手自动分批选刊：在单包限制、请求预算和公平性约束下，把全部/标签范围确定性拆成用户能检查的任务，而不是让模型编造几百个键。
2. 等义翻译、同义词、相关概念分层审批；当前提示词不能保证模型永远不会泛化主题。
3. 统一检索计划和能力编译：先明确各源 AND/OR/NOT 支持及降级，再调整请求协议；不能把多次 OR 搜索说成精确布尔检索。
4. 安装崩溃恢复与后台化导入：保留旧可用版本，记录候选安装阶段；消除手工处理 `installing` 和遗留环境修复锁的需要。
5. 远程部署：反向代理鉴权、TLS、最小数据库权限、备份恢复演练；不能因为本机页面可用就直接无保护开放公网。
6. 长期采集质量：监控 RSS 窗口漏采、摘要覆盖率和主题相关性；本轮测试不替代多日运行和逐源联网验收。
7. 数据增长治理：查询分页与索引实测、按执行状态归档运行文件、磁盘告警；清理必须区分可丢缓存与业务数据，默认不删采集结果。
