# 系统架构

## 分层

### 1. 模块层

模块描述一种业务领域，而不是一个网站。当前固定模块为 `news`、`paper`、`patent`。模块声明：

- 默认资源类型；
- 支持的采集模式；
- 面板中的查询字段名称；
- 展示顺序与启用状态。

### 2. 来源层

来源插件只负责外部系统交互和数据标准化。插件不能直接访问业务数据库，也不能控制任务状态。每个插件必须声明模块、唯一名称、物理表、资源类型、支持模式和协议版本。

### 3. 执行层

执行层把用户输入转换成 `CollectionRequest`，读取来源配置，依次运行兼容来源，并记录来源级失败。一个来源失败不会中断其他来源。

采集模式：

- `search`：围绕关键词即时检索，适合新闻和支持站内搜索的论文平台。
- `sync`：按游标或时间范围增量同步，适合期刊目录、论文元数据和专利公开数据。

### 4. 存储层

每个业务模块拥有一张资源表：`news_resources`、`paper_resources`、`patent_resources`。同一模块中的来源通过 `source_key` 隔离，新增来源不会新增物理表。

稳定资源身份优先使用来源文章编号、DOI、专利号等标准标识符，否则使用规范化 URL。搜索词不参与资源身份计算。

### 5. 控制层

Flask API 和控制台只负责任务提交、配置管理、状态查询和结果展示。它们不包含网页解析逻辑。

## 数据库边界

| 表 | 职责 |
| --- | --- |
| `schema_migrations` | 当前数据库模式版本 |
| `sources` | 来源目录、启停、采集上限和配置 |
| `monitors` | 每日或每周运行的关键词监控 |
| `monitor_sources` | 监控主题选择的来源 |
| `monitor_runs` | 一次手动或定时运行 |
| `news_resources` | 百科、RSS、搜索结果等新闻模块资源 |
| `paper_resources` | 全部论文及论文专业字段 |
| `patent_resources` | 全部专利及专利专业字段 |
| `monitor_resource_matches` | 监控主题长期命中的资源 |

`monitor_sources` 同时保存任务在各来源上的配置和增量游标；
`monitor_runs.source_results_json` 保存一次运行中各来源的状态摘要。JSON 不保存实体 ID
关系，监控与资源的多对多关系仍由 `monitor_resource_matches` 维护。

## 中文论文 Agent 的接入位置

AI Agent 属于来源管理控制面，不属于日常采集执行面：

1. Agent 识别期刊平台并生成候选配置。
2. 确定性验证器抓取小样本并检查元数据质量。
3. 人工审核后作为 `paper` 模块来源写入 `sources`。
4. 已发布适配器通过普通 `search` 或 `sync` 任务运行，不再调用模型。

旧文献采集器中的平台适配器应放在独立的 `collector/sources/paper` 包中，对外只暴露一个或少量论文插件入口，避免自动发现器把内部适配类误认为顶层来源。
