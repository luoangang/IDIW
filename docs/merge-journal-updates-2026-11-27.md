## 部署顺序

本次合并不等于部署。合并检查时三个本机计划服务均已停止，本次不改变其状态。

1. 备份当前数据库和运行配置，确认 API、Scheduler、Worker 已停止且无活动包运行。
2. 使用当前平台虚拟环境运行：

   ```powershell
   .\.venv\Scripts\python.exe -X utf8 platform_main.py init-db
   ```

   该命令应用 005 迁移，为已登记且存在的结果表增加 `sys_last_changed_at`、`sys_change_count` 及索引。MySQL DDL 可能自动提交，并非整库事务回滚；不要省略备份。历史变更次数无法还原，旧行初始化为 1。
3. 按需导入/升级期刊包，一次检查一个包；保留原表和配置。不应仅为目录数量一次性启动几千本采集。新目录的选刊键和上限必须通过现有任务参数校验。
4. 新包若需 AI 自动选择，先登记并审阅 `configs/assistant-source-profiles.json` 的检索范围、语言及时间模式，不能把当期本地过滤说成历史全库检索。
5. 启动三个服务，检查 `/health/ready`、`/system`、数据预览及小规模手动采集，再恢复原定时计划。没有新包导入需求时，仍需先完成第 2 步再启动合并后的服务。
