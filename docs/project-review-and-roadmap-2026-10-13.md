# 当前平台审视与下一阶段实施路线

日期：2026-10-13。

本文区分代码审视结论、已完成的验证与未来建议。本轮没有修改业务代码、数据库、插件或监控任务，也没有执行新的采集任务。本文不是功能已经完成的说明。

后续进展：用户确认 USPTO 号码查询需求，并授权尝试 RSS 包；RSS 原型及独立测试结果见 [通用 RSS 包选型与实测](rss-multi-feed-evaluation-2026-10-13.md)。下面的测试数量和插件登记是审视当时的快照，不能替代后续实施状态。

## 1. 本次确认的需求

1. 文献：增加能够按关键词获取标题、摘要、作者、机构等元数据的大型学术来源；已有 WoS 网页自动化尝试不再作为默认路线。
2. 专利：用户随后明确来源限定 USPTO，已经有美国专利号；先跑通号码查询标题、申请人、申请日期、摘要等元数据，不做关键词发现。
3. 主题监控：监控“具身智能”和“军事智能体”，扩展新闻来源，每日采集、每周生成可追溯的 AI 情报报告。
4. 网站：按采集管理工作流程完善功能，优先桌面端，不建设手机适配或完整多租户用户系统。

继续保留以下架构约束：独立插件包、文件交换协议、每个包一张原始结果表、六类目录、任务与资源匹配关系。AI 分析不应替代或覆盖原始采集结果。

## 3. 按优先级处理的基础问题

### P1：任务崩溃后可能永久占用监控

位置：`crawler_platform/executor.py:23`、`:194`、`:201`；`crawler_platform/storage.py:538`、`:660`。

执行前读取包清单、创建工作目录、写请求文件等操作位于保护范围外；Worker 主循环也没有异常恢复。数据库异常或包目录异常可能导致 Worker 退出。

数据库虽然有 lease_expires_at 和 heartbeat_at，但只在领取时写入，未实现持续心跳或过期任务回收。领取逻辑只读取 queued，遗留 running 任务不会自动恢复；同一监控存在活动运行时，又不允许重新入队。

建议：

- 将整个执行生命周期纳入异常处理，区分包错误、平台错误与存储错误。
- 用真实心跳续租；回收过期任务时校验租约令牌，拒绝旧进程迟到提交。
- 有限次数重试、退避、明确终态；仅重试可恢复故障。
- 平台重启后恢复未完成任务，刷新父运行状态。
- 超时或取消应终止整个进程树，避免浏览器等子进程残留。

验收：运行中关闭 Worker 后重启，不永久停留 running；数据库短暂断连后恢复；迟到结果不能提交到已经换租约的任务。

### P1：定时任务没有使用保存的时区

位置：`crawler_platform/storage.py:357`、`:630`、`:648`、`:1130`。

任务保存了 timezone，但 `_next_run` 使用 UTC 日期和用户填写的时间直接组合，未进行时区转换。MySQL 的 NOW 又依赖数据库会话时区，调度需要统一时间基准。

建议：按照任务时区计算下一次本地触发时间，再转换为 UTC 保存；数据库连接统一 UTC，网页按选定时区展示。Windows 运行环境需要提供 IANA 时区数据。调度去重应使用计划触发时刻，而不是当前轮询分钟，并明确错过周期后的补跑策略。

验收：北京时间每天 09:00 能在 01:00 UTC 触发；覆盖每日、每周、跨日和服务重启场景。

### P1：翻页游标不能直接充当每日增量进度

位置：`crawler_platform/storage.py:596`、`:812`；`crawler_packages/news/sina_news/crawler.py:170`。

平台的 time_range 始终为空，并把插件 next_cursor 保存到下一次运行。新浪新闻游标记录 page/offset；在最新优先的动态列表中，第二天从旧页继续会跳过新插入的第一页内容。

建议：分开定义“本批次分页位置”和“跨周期成功水位”。每天从最新结果开始，带有固定的本批次时间窗口；对迟到收录设置可配置重叠窗口，依赖幂等入库去重。分页只在该批次内继续；失败时不能提前推进成功水位。对于滚动列表，还要考虑抓取过程中新增记录造成的页位移。

验收：两次采集之间插入新文章，第二次能发现；重复文章不重复入库；失败后重试不漏文章。不要在没有心跳回收的情况下直接启用无限自动续采。

### P1（外网部署前）：认证与执行边界尚未形成闭环

位置：`crawler_platform/api.py:49`；`crawler_platform/dashboard.html` 的 API 请求封装。

未配置 token 时 API 无认证；配置 token 后网页没有携带该 token，管理功能会收到 401。导入插件会执行代码，虚拟环境只隔离依赖，不是安全沙箱。

建议：先完成管理页面与 API 的认证闭环；限制导入和本地路径接口；仅运行可信包。服务器使用低权限服务账户，配置凭据隔离、日志脱敏、TLS 和访问控制。接收不可信第三方包时，再引入容器等隔离措施。无需因此立即建设复杂用户系统。

验收：未认证请求不能导入或执行包；已认证网页可以正常操作；密钥不出现在前端、下载文件或日志中。

### P2：前端无法表达完整的监控任务

位置：`crawler_platform/dashboard.html:191`；`crawler_platform/api.py:165`。

创建表单固定提交 manual；没有别名、每天/每周、时区等配置。后端虽支持创建定时任务，却没有任务编辑、暂停/恢复、取消或重试的完整接口。运行详情未提供受控的进程日志读取入口。

建议：先补业务操作，再调整视觉。所有操作需要明确的加载、失败、空数据和成功状态，重复点击必须幂等。

### P2：协议的输入模式需要扩展

位置：`crawler_platform/protocol.py:133`；`crawler_platform/storage.py:333`。

当前能力声明只有 incremental，任务必须有 query。关键词搜索、专利号查询、整站 RSS 监测和文件导入不是同一种输入。

建议发布向后兼容的协议小版本，增加支持的 input_modes，以及经过 Schema 校验的结构化输入。建议模式为 keyword、identifier、feed、file。旧包继续使用 query；界面和任务校验依据包支持的模式，不把专利号、文件路径或 RSS 地址硬塞进关键词字段。

## 4. 文献来源接入建议

### 推荐顺序

| 来源 | 建议 | 前置条件与局限 |
| --- | --- | --- |
| OpenAlex | 第一批实现关键词 API 包 | 官方 REST API，基础使用免费；重用量有计费；摘要覆盖不完整，须记录缺失 |
| arXiv | 第二个面向 AI 的补充包 | 官方 API 支持检索，返回标题、作者、摘要等；属于预印本，不能等同已同行评审论文 |
| Scopus | 权限核验通过后实现 | API Key 不自动授予产品数据权限；需要机构或合作授权；检索与摘要详情接口分别验收 |
| Google Scholar | 不作为默认无人值守主源 | 官方不提供批量记录访问，要求自动化遵守 robots.txt；可保留人工检索或提醒作为补充 |
| WoS | 暂不重启网页自动化路线 | 既有浏览器方案不稳定；官方 API 授权和人工导出解析是另两种路线，不能由网页失败推断也不可用 |

OpenAlex 优先是工程上的选择，不是论文质量排序。原始元数据优先保留 DOI、标题、摘要、作者、机构、来源期刊、发表时间、记录更新时间、类型、原始链接和字段缺失情况。不同来源同一 DOI 在分析层关联，保留每个包的原始记录。

OpenAlex 的开放元数据许可不意味着链接的论文全文也具备同样许可。向企业提供数据或将摘要发送给第三方 AI 时，应核对具体来源的授权范围。

验收：每个主题取一批结果，统计摘要与机构覆盖率；验证日期过滤、分页、429 退避、缺失 DOI、重复入库和连续两天增量。Scopus 先用少量样本验证实际可取字段，再编写完整包。

官方资料：[OpenAlex API](https://help.openalex.org/api/)、[arXiv API](https://info.arxiv.org/help/api/user-manual.html)、[Scopus 认证与权限](https://dev.elsevier.com/tecdoc_api_authentication.html)、[Google Scholar 官方帮助](https://scholar.google.com/intl/us/scholar/help.html)。

## 5. 专利号查询最小闭环

最新确认：数据来自 USPTO，用户已有专利号，只需要检索美国专利元数据。下一步核验 USPTO 当前可用接口、授权条件和号码类型，再用实际号码样本测试；不需要先实现全球覆盖。

此前 EPO OPS 建议仅保留为未来扩展参考，不再是本阶段首选。USPTO 的申请号、公开文献号、授权专利号不能当作一个格式直接互换；具体接口返回哪些字段仍需验证。

建议输出字段：

- country、publication_number、kind_code、application_number。
- title、abstract、abstract_language。
- applicants、inventors；如有当前权利人，应另存，不混同原始申请人。
- filing_date、publication_date、priority_date。
- ipc、cpc、source_url、fetched_at。

申请号、公开号和授权文献号需要明确区分。规范化号码后查询，保留种类代码；同一申请的不同公开版本和同族专利不应第一步就粗暴合并。缺失摘要返回空值和缺失原因，不能由 AI 编造。

流程：号码输入 -> 格式识别 -> 来源查询 -> XML/JSON 解析 -> 协议校验 -> 专利包结果表 -> 详情页/API。

验收：使用至少 20 个真实样本，包含有效号码、重复号码、无效号码、不同号码格式、无摘要与限流情况；按国家统计命中率与字段完整率。号码查询跑通后，关键词发现作为独立能力接上。

官方资料：[EPO OPS 服务与认证](https://www.epo.org/en/searching-for-patents/data/web-services/ops)。

## 6. 新闻扩展与两主题周报

### 第一批候选 RSS

| 来源 | 本机验证结果 | 初步主题方向 | 地址 |
| --- | --- | --- | --- |
| IEEE Spectrum | HTTP 200，30 条 | AI、机器人、工程技术 | https://spectrum.ieee.org/feeds/feed.rss |
| Breaking Defense | HTTP 200，30 条 | 国防技术与产业 | https://breakingdefense.com/full-rss-feed/ |
| Defense News | HTTP 200，25 条 | 国防产业、机构与装备新闻 | https://www.defensenews.com/arc/outboundfeeds/rss/?outputType=xml |
| Naval News | HTTP 200，10 条 | 海军与相关国防技术 | https://www.navalnews.com/feed/ |

这些是一次性可用性检查，不是已导入插件。它们大多是整站订阅，不提供站内关键词搜索；推荐一个通用 RSS 包接受多个 feed_urls，保留 source_site，并在本地按主题宽松匹配。随后增加官方研究机构、实验室、企业公告，逐站验证公开接口、订阅或栏目结构。

每天采集，周报每周生成。若只每周读取一次短 RSS 列表，可能遗漏已经移出列表的文章。RSS 描述往往是摘要，不是正文；需要全文时，再评估单独的合规补全文能力。

### 主题配置

| 主题 | 核心叫法 | 可扩展的相关词，不直接视为完全同义 |
| --- | --- | --- |
| 具身智能 | 具身智能、具身人工智能、embodied AI、embodied intelligence | embodied agents、robot foundation models、vision-language-action |
| 军事智能体 | 军事智能体、military AI agents | agentic AI/autonomous agents 与 military/defense/defence 联合匹配 |

采集优先保证召回，之后再评分、聚类和排序。“智能体”“多智能体”单独使用容易产生大量无关结果；来源原生检索语法应由插件转换，不能把所有主题扩展词都当作一个字符串直接搜索。

当前 Google RSS 等插件主要使用 query，并未完整利用 aliases；添加任务别名字段本身不会自动扩大这些来源的检索范围。

### 周报独立于爬虫插件

建议流水线：主题任务 -> 每日采集 -> 原始包表 -> 统一分析视图 -> 相关性评分与事件聚类 -> AI 草稿 -> 审核与导出。

- 不删除跨来源的独立报道；相同 DOI、规范化 URL、专利文献号用于关联，事件聚类用于减少周报重复叙述。
- 分别记录发布时间、首次采集时间、首次匹配该主题的时间，处理迟到收录和旧资料新发现。
- 每个事实要引用记录 ID、原始链接和日期；事实与分析判断分开。
- 仅有标题或摘要的资料明确标记依据，不能假装阅读了完整文章。
- 爬取文本作为不可信数据；报告模型不得执行其中指令，默认不赋予操作数据库或执行脚本的工具权限。
- 保存报告时间范围、输入记录快照或内容摘要、模型/提示词版本、状态与费用统计；周报失败可单独重试，不必重新爬取全部资料。
- 设置单篇输入长度、总 token 与费用预算；先逐条提炼，再按主题汇总。
- 第一版输出 Markdown 和结构化 JSON；自动发布、邮件推送和复杂报告工作流后置。
- 报告应披露本周来源失败或覆盖不足，避免把“未采到”写成“没有新进展”。

建议周报栏目：本周要点、重要新闻、新论文、新专利、重点机构、分析判断、来源覆盖与参考链接。

## 7. 网站功能按使用顺序组织

保留多页面模式，避免把所有表单放回同一个首页。六个入口各自承担明确职责：

| 页面 | 第一阶段必须具备的操作 |
| --- | --- |
| 概览 | 待执行、运行中、最近失败、近期新增、来源健康、下一次计划运行 |
| 监控任务 | 输入模式、关键词/号码、主题扩展词、来源选择、每天/每周、时区、编辑、暂停/恢复、立即执行 |
| 采集源 | 分类筛选、包导入、默认配置、能力/字段展示、环境检查、重建、升级结果 |
| 运行记录 | 父任务与插件结果、阶段与耗时、结构化错误、日志查看、取消、可控重试 |
| 数据 | 按任务/来源/日期筛选、摘要预览、详细字段、来源链接、JSON/CSV 导出 |
| 情报周报 | 主题、周期、生成状态、报告阅读、证据链接、草稿审核与导出 |

全局默认配置与任务覆盖配置应同时显示生效值，避免用户不清楚本次用哪套参数。密钥只显示是否已配置，不回传明文。来源暂时无数据、采集失败和被禁用需要有不同状态。

UI 验收包含桌面端完整流程和截图检查，不需要手机适配。优先补定时、编辑、暂停和日志入口，周报页面随报告能力上线。

## 8. 数据库与工程优化边界

- 保留每包一张原始表和 monitor_resource_matches，不因新增分析就再次改回所有资源共用主表。
- 对分析暴露统一的只读投影，例如标题、摘要、作者/机构、日期、来源、主题、包 ID 和 resource_uid；具体字段由协议映射。
- 现有跨包预览使用 UNION ALL 与统计排序，数据增长后需要量测，再增加包表日期/身份索引、稳定分页或可重建的检索索引。当前阶段不必先引入搜索集群。
- 插件升级应在候选版本安装成功后才切换活动版本，保留旧版本和用户默认参数，失败升级不能破坏原先可运行的包。
- 建立真正追加的数据库迁移记录、备份与恢复验证，不应通过覆盖已有迁移 checksum 假装执行了新迁移。
- 协议发布固定测试向量与包侧公共辅助库，新增包自动发现测试；网络样本测试与离线协议测试分开。
- 平台 Python 与插件 Python 解耦仍是长期方向；API/RSS 包先使用已验证环境，不急于为每个包引入容器集群。
- 为每日任务补充运行时长、错误类型、来源限流和新增比例指标；配置日志与工作目录保留期限。

## 9. 推荐实施顺序与交付标准

| 阶段 | 交付 | 验收标准 |
| --- | --- | --- |
| A | 执行恢复、时区、增量时间窗口、最小任务管理与日志 | 崩溃重启不挂死；指定时区准时；连续执行不漏新数据；失败可定位 |
| B | 两主题配置、通用 RSS 包、周报草稿 | 每日入库；一周报告可复现；每个事实有引用；重复报道聚类但原文保留 |

| D | 专利号码查询包 | 真实号码样本验收；国家覆盖明确；申请人与日期语义正确；重复查询幂等 |
| E | 网站管理闭环与服务器部署加固 | 编辑/暂停/取消/重试/导出可用；认证网页正常；备份与服务恢复经过验证 |

阶段 E 中的基本任务管理和日志入口应提前随 A 完成；外网部署的认证加固也不能等到最后。新闻周报先形成可展示闭环，论文和专利随后接入相同分析流程，不必等待所有来源齐全。

暂缓：全系统重构、完整用户/组织系统、手机端、代理池集群、分布式调度、无法证明稳定的登录态网页自动化，以及无数据量依据的复杂分析表设计。
